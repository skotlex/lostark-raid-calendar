# 로스트아크 길드 레이드 편성표

요일별 레이드 슬롯에 길드원이 캐릭터를 배치하는 웹앱입니다. 기존에 쓰던 Google 시트를
대체합니다.

시트에서 불편했던 세 가지를 고치는 것이 목적입니다.

1. **캐릭터 스펙이 `#REF!`로 깨져 있었습니다** → 로아 공식 OpenAPI로 클래스·템레벨·
   전투력·직업 각인·아크그리드를 자동으로 가져옵니다
2. **매주 인원을 손으로 지워야 했습니다** → 화요일 0시에 자동으로 비워집니다.
   화요일 레이드만 그날 저녁 공대가 끝나는 수요일 오전 6시까지 남습니다.
   고정 공대는 자리 단위 또는 레이드 단위로 승계를 켤 수 있습니다
3. **셀 편집이라 남의 신청을 실수로 지우기 쉬웠습니다** → 슬롯 단위 화면과 편집 이력을
   두었습니다

## 무엇을 할 수 있나요

- **편성표** — 요일별로 레이드 슬롯을 보여줍니다. 칸에 닉네임을 치면 조회·등록·배치가
  한 번에 끝납니다. 카드로 보는 `전체`와 8인이 한 줄에 들어오는 `간략` 두 가지 보기가
  있습니다
- **경고** — 템레벨 미달, 같은 레이드 중복(난이도가 달라도 한 주에 한 번입니다),
  서폿 자리의 딜러를 알려줍니다. 알리기만 하고 막지는 않습니다
- **시너지 요약** — 4인 파티 단위로 어떤 시너지가 들어왔는지, 누가 주는지 보여줍니다
- **고정 현황** — 다음 주로 넘어갈 자리를 모아 보고 여기서 풉니다
- **캐릭터 관리** — 원정대 불러오기, 스펙 갱신, 원정대 묶기(클레임), 정리
- **숙제 관리** — 편성표에 넣은 내 캐릭터의 이번 주 숙제와 골드를 모아 봅니다.
  레이드 시각이 지나면 다녀온 것으로 봅니다. 골드를 받는 세 개는 줄 순서가 정하며
  번호 뱃지를 끌어 옮길 수 있습니다
- **실시간 표시** — 같은 편성표를 보고 있는 사람이 머리줄에 뜨고, 남이 만지고 있는
  칸에 이름표가 얹힙니다. 남이 저장하면 내 화면도 알아서 갱신됩니다
- **편집 이력** — 누가 무엇을 바꿨는지 시간순으로 남습니다

## 직접 준비해야 하는 것들

이 저장소에는 인증 정보가 들어 있지 않습니다. 본인의 키와 DB가 필요합니다.

### 1. 로아 OpenAPI 키

[개발자 포털](https://developer-lostark.game.onstove.com)에서 클라이언트를 만들면 JWT가
바로 발급됩니다. 무료입니다.

한도는 **키마다 분당 100회**입니다. 클라이언트를 여러 개 만들어
`LOSTARK_API_KEYS`에 쉼표로 나열하면 그만큼 늘어나고, 요청도 키 수만큼 동시에 나갑니다.
캐릭터가 200명쯤 되어 `전체 갱신`이 느껴질 때만 고려하시면 됩니다.

### 2. 디스코드 앱

[개발자 포털](https://discord.com/developers/applications)에서 앱을 만들고 OAuth2의
클라이언트 ID·시크릿을 받습니다. 길드(서버) ID도 필요합니다. 디스코드에서 개발자 모드를
켜면 서버 이름을 우클릭해 복사할 수 있습니다.

**길드 멤버가 아니면 편성표를 볼 수 없습니다.** 로그인이 곧 입장 심사입니다.

같은 앱의 `Bot` 탭에서 봇을 만들고 `Reset Token`으로 토큰을 받아
`DISCORD_BOT_TOKEN`에 넣어 주세요. **그다음 그 봇을 길드에 초대해야 합니다.**
`OAuth2 › URL Generator`에서 `bot` 스코프만 고르면 초대 링크가 나옵니다. 권한은
하나도 주지 않아도 됩니다.

이 봇은 **로그인 이후에도 아직 길드원인지 확인하는 데만** 쓰입니다. 세션은 30일짜리라
이게 없으면 길드를 나간 사람이 한 달 내내 들어옵니다. 메시지를 읽거나 보내지 않으므로
특권 인텐트도 켤 필요가 없습니다. 토큰을 넣지 않으면 재검사만 조용히 쉬고 나머지는
그대로 동작합니다.

### 3. Postgres

[Supabase](https://supabase.com) 무료 프로젝트면 충분합니다. 지역은 **서울
(`ap-northeast-2`)** 을 고르세요. Vercel 함수도 서울(`icn1`)에 두므로 둘이 같은 지역에
있어야 합니다. **만든 뒤에는 지역을 바꿀 수 없습니다.**

대시보드의 Connect 화면에서 **접속 문자열 두 개**를 복사합니다. Connection Method를
바꿔가며 각각 복사하셔야 합니다.

| 고를 것 | 포트 | 쓰는 곳 |
|---|---|---|
| **Transaction pooler** | `6543` | 앱 런타임 |
| **Session pooler** | `5432` | 스키마 작업(`prisma db push`) |

**맨 위의 `Direct connection`은 쓰지 마세요.** 무료 플랜에서는 IPv6 전용이라 대부분의
가정용 회선과 Vercel에서 연결되지 않습니다. 같은 5432 포트라도 `Session pooler` 쪽을
쓰셔야 합니다.

`[YOUR-PASSWORD]` 자리표시자를 실제 비밀번호로 바꾸는 것을 잊지 마세요. 비밀번호에
`/ ? # % @ :` 가 들어 있으면 URL 파싱이 깨지므로 영숫자로 리셋하시는 편이 편합니다.

무료 프로젝트는 **일주일간 활동이 없으면 정지**되고, 그때는 대시보드에서 직접
`Resume project`를 눌러야 합니다. 배포하면 하루 한 번 도는 크론이 이를 막아 줍니다
(아래 배포 항목).

무료 한도에서 먼저 닿는 것은 **Egress(월 5GB)** 입니다. 컴퓨트 시간은 세지 않습니다.
넘겨도 **과금되지 않고** 다음 결제 주기까지 제한이 걸립니다. 조직(Organization)의
`Usage` 페이지에서 확인하실 수 있습니다.

### 4. 환경변수

```bash
cp .env.example .env.local
```

`.env.local`을 열어 값을 채웁니다.

| 이름 | 값 |
|---|---|
| `DATABASE_URL` | Supabase Transaction pooler 문자열 (포트 `6543`) |
| `DATABASE_URL_UNPOOLED` | Supabase Session pooler 문자열 (포트 `5432`) |
| `LOSTARK_API_KEY` | 로아 OpenAPI JWT |
| `INSTANCE_SESSION_SECRET` | 세션 쿠키 서명용 랜덤 문자열 |
| `DISCORD_CLIENT_ID` | 디스코드 앱 ID |
| `DISCORD_CLIENT_SECRET` | 디스코드 앱 시크릿 |
| `DISCORD_GUILD_ID` | 길드(서버) ID |
| `DISCORD_BOT_TOKEN` | 길드 멤버십 재검사용 봇 토큰 |
| `CRON_SECRET` | keep-alive 크론 보호용. **Vercel에만** 넣으면 됩니다 |

**어느 것에도 `NEXT_PUBLIC_` 접두사를 붙이지 마세요.** 붙는 순간 브라우저 번들로 새어
나갑니다.

### 5. 실행

```bash
npm install
npm run db:generate    # Prisma 클라이언트 생성 (커밋되지 않으므로 필요합니다)
npm run db:push        # 스키마를 DB에 반영
npm run db:lock        # 공개 API 통로 차단 (설명은 바로 아래)
npm run db:seed        # 기본 인스턴스 생성
npm run dev
```

`http://localhost:3100`으로 열립니다. 디스코드 앱의 Redirects에
`http://localhost:3100/api/auth/discord/callback`을 등록해야 로그인이 됩니다.

#### `db:lock`을 건너뛰지 마세요

Supabase는 프로젝트를 만들 때부터 **public 스키마에 만드는 표를 공개 API로 내보내도록**
설정해 둡니다. `prisma db push`로 세운 표에도 그대로 걸려서, 아무것도 하지 않으면
`https://<프로젝트>.supabase.co/rest/v1/Character` 같은 주소로 길드원 데이터를 읽고
쓰고 지울 수 있는 상태가 됩니다. 여기에 쓰이는 `anon` 키는 **브라우저에 넣으라고 만든
키라 비밀이 아닙니다.**

이 앱은 `supabase-js`를 쓰지 않고 Prisma로만 DB에 붙으므로 그 통로가 아예 필요 없습니다.
`npm run db:lock`이 표마다 RLS를 켜고 공개 롤의 권한을 회수해 통로를 막습니다.
접속은 `postgres` 롤로 하고 이 롤은 RLS를 통과하므로 **앱 동작에는 영향이 없습니다.**

여러 번 돌려도 안전합니다. `npm run db:lock -- --check`로 지금 상태만 볼 수 있습니다.
**표를 새로 만든 뒤에는 한 번 더 돌려 주세요.**

## 배포 (Vercel)

지역은 `vercel.json`에 **서울(`icn1`)** 로 고정해 두었습니다. DB와 같은 지역이어야
페이지마다 나가는 여러 번의 쿼리가 국제 구간을 왕복하지 않습니다. **DB를 다른 지역에
만드셨다면 이 값도 함께 바꾸셔야 합니다.** 한쪽만 옮기면 오히려 느려집니다.

같은 파일에 하루 한 번 도는 크론(`/api/keep-alive`)도 들어 있습니다. Supabase 무료
프로젝트가 일주일 미사용으로 정지되는 것을 막습니다.

### 1. 프로젝트 연결

Vercel에서 이 저장소를 Import합니다. 프레임워크는 Next.js로 자동 인식됩니다. 빌드 명령은
그대로 두세요. `npm run build`가 `prisma generate`를 먼저 돌립니다. 생성된 클라이언트는
커밋하지 않으므로 이 단계가 없으면 빌드가 깨집니다.

### 2. 환경변수

위 표의 값을 Production·Preview 양쪽에 넣습니다. `Import .env` 버튼으로 `.env.local`을
그대로 올릴 수 있습니다.

### 3. 디스코드 리다이렉트 URI

콜백 주소는 **접속한 도메인에서 만들어집니다.** 그래서 디스코드 앱 설정에 실제 도메인을
등록해야 합니다. 개발용 주소도 함께 남겨두세요.

```
https://<배포-도메인>/api/auth/discord/callback
http://localhost:3100/api/auth/discord/callback
```

Preview 배포는 도메인이 매번 바뀌어 로그인이 되지 않습니다. 확인은 Production에서 하시는
편이 편합니다.

### 4. 스키마와 기본 데이터

쓰던 DB를 그대로 가리키면 할 일이 없습니다. 새 DB라면 로컬에서 한 번 돌립니다.

```bash
npm run db:push
npm run db:lock
npm run db:seed
```

### 5. 배포 후 확인

- `/`를 열면 `/login`으로 넘어가는지
- 디스코드 로그인 후 길드 멤버만 들어오는지
- 편성 칸에 닉네임을 넣어 로아 조회가 되는지
- Settings → Cron Jobs에 `/api/keep-alive`가 등록됐는지. `Run` 버튼이 **200**을
  돌려주면 인증까지 정상입니다
- 함수가 서울에서 도는지. 응답 헤더 `X-Vercel-Id`가 `icn1::icn1::...` 이어야 합니다.
  뒤쪽이 다른 지역이면 `vercel.json`이 배포에 반영되지 않은 것입니다

```bash
curl -sI https://<배포-도메인>/login | grep -i x-vercel-id
```

**환경변수를 바꾼 뒤에는 반드시 재배포해야 합니다.** Vercel은 값을 빌드 시점에 배포에
굳혀 넣어서, 기존 배포에는 반영되지 않습니다.

**`Redeploy`는 그 배포가 가리키던 커밋을 다시 씁니다.** 푸시 이전 배포에 대고 누르면
옛 코드가 프로덕션으로 올라가면서도 `Ready`·`Production` 배지는 그대로 붙습니다.
새 커밋을 올리려면 목록에서 **그 커밋의 배포를 찾아** 다루셔야 합니다.

## 권한과 개인정보

- 로아 OpenAPI는 **공개된 캐릭터 정보만** 읽습니다. 계정 정보에는 접근하지 않습니다
- API 키와 디스코드 시크릿은 서버에서만 쓰입니다. 브라우저로 전달되지 않습니다
- 디스코드에서는 `identify`와 `guilds.members.read`만 받습니다. 메시지를 읽거나 보내지
  않습니다
- **길드를 나가시면 최대 한 시간 안에 접속이 끊깁니다.** 서버가 주기적으로 멤버십을
  다시 확인합니다. 이때도 확인하는 것은 길드에 남아 있는지 하나뿐입니다
- **입장한 사람은 누구의 편성이든 고칠 수 있습니다.** 공대장이 대신 넣어주는 일이 흔해서
  일부러 막지 않았습니다. 대신 누가 무엇을 바꿨는지 편집 이력에 남습니다
- 캐릭터의 주인은 로아 API가 알려주지 않습니다. **원정대 묶기는 본인 신고**이며,
  검증되는 것은 디스코드 계정뿐입니다

## 개발

| 문서·파일 | 내용 |
|---|---|
| `CLAUDE.md` | 프로젝트 컨텍스트와 규칙. 구조를 바꾸기 전에 읽어주세요 |
| `prisma/schema.prisma` | 데이터 모델. 슬롯과 배정의 분리가 핵심입니다 |
| `src/lib/week.ts` | 주차 계산. 수~월은 화요일 0시, 화요일은 수요일 6시에 비워집니다 |
| `src/lib/positions.ts` | 자리와 파티. 8인은 4인 파티 둘, 4인은 하나입니다 |
| `src/lib/synergy.ts` | 시너지와 딜/서폿 판정. 트라이포드가 클래스 표보다 우선합니다 |
| `src/lib/armory.ts` | 로아 응답 정규화. 유닛 테스트가 있습니다 |
| `src/lib/lostark.ts` | 로아 API 클라이언트. 키 분배와 429 백오프 |
| `src/lib/arkGridCores.ts` | 아크그리드 코어 이름 → 단계 표 (30직업 540코어) |
| `src/lib/members.ts` | 원정대 클레임. 캐릭터의 주인을 정하는 유일한 경로입니다 |
| `src/lib/history.ts` | 편집 이력. 기록을 남기는 곳을 여기 하나로 모았습니다 |
| `src/lib/raidRewards.ts` | 클리어 골드·더보기 비용·입장 레벨컷 표. 확인한 값만 넣습니다 |
| `src/lib/homework.ts` | 숙제 판정. 레이드 시각이 지났는지로 가릅니다 |
| `src/lib/homeworkOrder.ts` | 골드를 받는 세 개를 정하는 순서 규칙. 서버와 화면이 함께 씁니다 |
| `src/lib/presence.ts` | 같이 보고 있는 사람. 폴링 한 갈래이며 간격이 혼자냐 아니냐로 갈립니다 |
| `src/lib/classEmblems.ts` | 직업 문장 아이콘. 파일은 `public/class-emblems/`에 함께 둡니다 |
